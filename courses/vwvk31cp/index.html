WSL2Ubantu安装miniconda

约 4889 字大约 16 分钟

2026-11-04

系统更新：偶尔记得在 WSL 终端里敲一下 sudo apt update && sudo apt upgrade 更新一下系统组件

将 Miniconda 安装到 /opt 目录是一个很好的选择，这能让所有用户都访问到这个统一的 Python 环境，也更便于你进行集中管理。

🐍 第一步：将 Miniconda 安装到 /opt

这个步骤的关键是使用静默安装模式，并明确指定安装路径。在 Ubuntu 终端中依次执行以下命令：

  1. 下载最新的 Miniconda 安装脚本：

    wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh

  2. 执行安装，指定路径为 /opt/miniconda3：

    sudo bash Miniconda3-latest-Linux-x86_64.sh -b -p /opt/miniconda3

    这里 -b 代表批处理模式（静默安装，无需交互），-p 用于指定安装路径。

  3. （可选）删除安装包：

    rm Miniconda3-latest-Linux-x86_64.sh

⚙️ 第二步：初始化 Conda 环境

安装完成后，需要初始化 Conda 才能正常使用 conda 命令。

  1. 运行 Conda 初始化命令：

    /opt/miniconda3/bin/conda init bash

    这条命令会修改你的 ~/.bashrc 文件，将 Conda 的相关路径和函数加入其中。

  2. 使配置立即生效：

    source ~/.bashrc

  3. 验证安装：

    conda --version

    如果能看到版本号输出，说明安装和初始化都成功了。

💡 第三步：关于 Jupyter Lab 的安装建议

建议安装 Jupyter Lab，尤其是考虑到你后续要运行生物信息学、分子对接等数据分析代码。Jupyter Lab 提供了一个交互式的编程环境，非常适合进行数据探索、可视化和逐步调试。

不过，不建议在 base 环境中直接安装。最佳实践是为 Jupyter Lab 创建一个独立的 Conda 环境，这能避免不同项目间的包版本冲突。

安装步骤：

  1. 创建一个专门的环境（例如命名为 jupyter_env）：

    conda create -n jupyter_env python=3.10

  2. 激活该环境：

    conda activate jupyter_env

  3. 安装 Jupyter Lab：

    conda install -c conda-forge jupyterlab

    为了后续在 Jupyter 中使用其他 Conda 环境，建议同时安装 ipykernel。

🚀 第四步：配置远程访问 Jupyter Lab

由于你的服务器是无图形界面的 WSL2 环境，需要通过 SSH 端口转发来在本地浏览器访问 Jupyter Lab。

  1. 启动 Jupyter Lab（在服务器端）： 在激活了 jupyter_env 环境的终端中运行：

    jupyter lab --no-browser --ip=0.0.0.0 --port=8888
    • --no-browser：不尝试在服务器上打开浏览器。
    • --ip=0.0.0.0：允许所有网络接口访问。
    • --port=8888：指定端口（你可以换成其他未占用的端口）。 启动后，终端会输出一个包含 token 的完整 URL，请复制保存。

  2. 建立 SSH 隧道（在你的远程 Windows 机器上）： 打开 PowerShell，运行以下命令。假设你的服务器 Tailscale IP 是 100.121.21.105：

    ssh -N -L 8888:localhost:8888 aikemi@100.121.21.105
    • -N：表示不执行远程命令，仅用于端口转发。
    • -L 8888:localhost:8888：将本地的 8888 端口转发到服务器的 8888 端口。 保持这个 PowerShell 窗口打开。

  3. 在本地浏览器中访问： 在远程 Windows 机器的浏览器中，访问 http://localhost:8888。将第一步中复制的 token 粘贴进去即可登录。

📌 注意事项

  • 权限问题：因为安装到了 /opt，后续安装新的 Conda 包时可能需要 sudo 权限。一个更简便的方法是，将 /opt/miniconda3 的所有权转移给你的用户：
    sudo chown -R $USER:$USER /opt/miniconda3
  • 环境切换：你可以创建多个 Conda 环境（如 bioinfo、molecular_docking）来隔离不同的项目依赖。
  • 内核注册：若想在 Jupyter Lab 中使用其他 Conda 环境，需要在该环境中安装 ipykernel 并手动注册：
    conda activate 你的其他环境名
python -m ipykernel install --user --name=环境名 --display-name="显示名称"

是的，原来的镜像（特别是 Conda 默认的 defaults 源）强烈建议删除。

如果不删，Conda 在安装包时会先去尝试连接官方源，发现连不上或者极慢后，才会切到中科大源。这不仅会拖慢速度，还会导致频繁报错。

下面为你提供从清理旧配置到完整应用中科大源的全部过程，请直接在 Ubuntu 终端中依次执行。

🧹 第一步：彻底清理旧的 Conda 源

  1. 移除所有现有的 channel（包括默认源）：

    conda config --remove-key channels

    (注意：如果报错说 CondaKeyError: 'channels': key 'channels' is not in the config file，说明你本来就是空的，直接跳过这一步即可。)

  2. 查看是否清理干净：

    cat ~/.condarc

    此时文件里应该没有 channels 相关的配置了。

⚙️ 第二步：配置中科大 Conda 源（全新添加）

依次执行以下命令，添加中科大的各个频道：

# 添加主源和 free 源
conda config --add channels https://mirrors.ustc.edu.cn/anaconda/pkgs/main/
conda config --add channels https://mirrors.ustc.edu.cn/anaconda/pkgs/free/

# 添加社区源（conda-forge 必备）
conda config --add channels https://mirrors.ustc.edu.cn/anaconda/cloud/conda-forge/

# 添加生信专属源（bioconda，对你做生信非常重要）
conda config --add channels https://mirrors.ustc.edu.cn/anaconda/cloud/bioconda/

# 设置安装时显示源地址
conda config --set show_channel_urls yes

验证配置：运行 cat ~/.condarc，你应该能看到 channels: 下面全是 mirrors.ustc.edu.cn 开头的地址，且没有 defaults。

🐍 第三步：清理并配置 Pip 的中科大源

Pip 在 Linux 下的配置文件通常位于 ~/.config/pip/pip.conf 或 ~/.pip/pip.conf。我们直接通过命令覆盖旧配置。

  1. 清理现有的全局 index-url 配置（如果之前配过别的）：

    pip config unset global.index-url

    (如果报错说 No such key，说明没配过，忽略即可。)

  2. 配置中科大源：

    pip config set global.index-url https://mirrors.ustc.edu.cn/pypi/web/simple

  3. （可选，但推荐）设置信任主机： 有时候 SSL 证书验证会出小问题，加上这个可以避免报错：

    pip config set global.trusted-host mirrors.ustc.edu.cn

验证配置：运行 pip config list，输出应该类似这样：

global.index-url='https://mirrors.ustc.edu.cn/pypi/web/simple'
global.trusted-host='mirrors.ustc.edu.cn'

🚀 第四步：实测速度

既然你正在配置环境，直接顺手测试一下。在当前终端（如果是 (base) 环境）执行：

测试 Conda 速度：

conda install numpy -y

你会看到下载进度条，且地址全是 https://mirrors.ustc.edu.cn/...，速度应该非常快。

测试 Pip 速度：

pip install requests

同样，瞬间就能安装完成。

💡 补充提醒：关于 .condarc 的层级

  • 你刚才在 /opt/miniconda3 下执行了 conda init，现在你的配置文件在用户目录下：/home/aikemi/.condarc。
  • 因为你的 Miniconda 安装在 /opt，如果有多个用户使用，每个用户都可以拥有自己独立的 ~/.condarc 镜像配置，互不干扰。
  • 如果你以后创建了新的环境（conda create -n bio_env），镜像源配置会自动继承，不需要在虚拟环境中重复配置。

以下是针对 Conda 和 pip 的完整源管理指令集，涵盖配置（中科大源）、查看和清除三大环节。

🐍 Conda 源管理

Conda 的源配置保存在 ~/.condarc 文件中，以下命令均通过 conda config 工具操作。

📝 配置中科大源

建议先清理旧源再配置，避免默认源或其他镜像源干扰。

① 清理旧源（谨慎操作）

# 备份当前配置（推荐）
cp ~/.condarc ~/.condarc.bak

# 查看当前已有的源
conda config --show channels

# 逐条删除不需要的源（例如清华源）
conda config --remove channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main/
conda config --remove channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/conda-forge/

注意：不建议用 conda config --remove-key channels 全部删除，这会把 defaults 也一并移除，可能导致某些基础包找不到。

② 添加中科大频道 按需添加以下频道（pkgs/r 和 pkgs/msys2 分别用于 R 语言和 Windows 工具链，可按需选择）：

# 核心 Python 包源（numpy、scipy 等，必须保留）
conda config --add channels https://mirrors.ustc.edu.cn/anaconda/pkgs/main/

# R 语言包源（建议添加，避免依赖缺失）
conda config --add channels https://mirrors.ustc.edu.cn/anaconda/pkgs/r/

# conda-forge 社区源（第三方生态主力）
conda config --add channels https://mirrors.ustc.edu.cn/anaconda/cloud/conda-forge/

# 生信专属源
conda config --add channels https://mirrors.ustc.edu.cn/anaconda/cloud/bioconda/

# 安装时显示包的来源地址
conda config --set show_channel_urls yes

pkgs/free 频道自 Conda 4.7 起已被官方废弃，不要添加，否则可能引发 CondaHTTPError。

③ 设置严格频道优先级（强烈推荐） 避免从多个频道混合解析依赖导致的版本冲突：

conda config --set channel_priority strict

🔍 查看 Conda 源

# 查看当前生效的频道列表
conda config --show channels

# 查看完整配置（包括 channel_priority 等）
conda config --show

# 查看配置文件原文
cat ~/.condarc

确认输出中所有地址均以 https://mirrors.ustc.edu.cn/ 开头，且没有 defaults 或其他镜像源残留。

🗑️ 清除 Conda 源

# 方式一：逐条移除指定频道
conda config --remove channels https://mirrors.ustc.edu.cn/anaconda/pkgs/main/
conda config --remove channels https://mirrors.ustc.edu.cn/anaconda/cloud/conda-forge/

# 方式二：移除全部 channels 配置（会将 defaults 也删除，慎用）
conda config --remove-key channels

恢复默认源：如果之前备份过 .condarc，直接覆盖还原即可；否则可以重新添加 defaults 频道：

conda config --add channels defaults

🐍 pip 源管理

pip 的配置通过 pip config 命令管理，配置文件通常位于 ~/.config/pip/pip.conf 或 ~/.pip/pip.conf。

📝 配置中科大源

# 设置中科大 PyPI 镜像
pip config set global.index-url https://pypi.mirrors.ustc.edu.cn/simple/

# 设置信任主机（避免 SSL 证书校验问题）
pip config set global.trusted-host pypi.mirrors.ustc.edu.cn

若之前配置过其他镜像源，set 命令会直接覆盖原有的 index-url。

🔍 查看 pip 源

# 查看当前所有 pip 配置
pip config list

输出中应包含：

global.index-url='https://pypi.mirrors.ustc.edu.cn/simple/'
global.trusted-host='pypi.mirrors.ustc.edu.cn'

也可以直接查看配置文件：

cat ~/.config/pip/pip.conf
# 或
cat ~/.pip/pip.conf

🗑️ 清除 pip 源

# 移除 index-url 配置，恢复默认官方源
pip config unset global.index-url

# 同时移除 trusted-host（如果之前设置过）
pip config unset global.trusted-host

unset 命令只删除显式配置项，pip 会自动回退到官方默认源 https://pypi.org/simple/。

也可以直接删除配置文件来彻底重置：

rm -rf ~/.config/pip/pip.conf
# 或
rm -rf ~/.pip/pip.conf

✅ 验证配置是否生效

Conda：实际触发一次网络请求来验证：

conda search numpy --info

观察输出中的 URL，应全部以 https://mirrors.ustc.edu.cn/ 开头。

pip：

pip install requests -v

在详细日志中确认下载地址指向 pypi.mirrors.ustc.edu.cn。

📌 注意事项

  • Conda 的 pkgs/free 已废弃，任何教程中出现添加 pkgs/free 的命令都应忽略。
  • channel_priority strict 是保证环境稳定性的关键设置，建议始终开启。
  • 如果配置后仍然走官方源，检查是否有环境变量（如 CONDA_CHANNELS、PIP_INDEX_URL）覆盖了配置文件中的设置。
  • 在 conda install 时使用 -c conda-forge 参数会强制绕过你配置的中科大镜像，直接走官方 conda-forge 源，注意避免。

这个报错非常经典。CondaKeyError 说明在 Conda 的配置逻辑里，defaults 并没有被当作一个“显式添加”的普通频道值。

由于 Conda 默认会自动包含 defaults，所以当你尝试用 remove channels defaults 时，它会告诉你“你没添加过这个，我删不掉”。

要彻底干掉它，最稳妥、最直接的方法就是直接编辑配置文件。请按以下两步操作：

🛠️ 方法一：直接修改配置文件（推荐，最干净）

  1. 打开配置文件 在终端输入以下命令，用记事本编辑器打开 .condarc：

    nano ~/.condarc

  2. 删除 defaults 这一行 在打开的界面中，找到 channels: 列表，用键盘方向键把光标移动到 - defaults 这一行的末尾，按 Ctrl + K 剪切（或者直接按 Backspace 删掉整行）。 修改后的文件应该长这样：

    channels:
  - https://mirrors.ustc.edu.cn/anaconda/cloud/bioconda/
  - https://mirrors.ustc.edu.cn/anaconda/pkgs/r/
  - https://mirrors.ustc.edu.cn/anaconda/cloud/conda-forge/
  - https://mirrors.ustc.edu.cn/anaconda/pkgs/main/
# 下面如果有 default_channels，也把它删除

  3. 保存并退出 按 Ctrl + O 保存，按 Enter 确认，再按 Ctrl + X 退出。

  4. 验证 再次运行：

    conda config --show channels

    这次输出里肯定就没有 defaults 了。

⚙️ 方法二：使用 nodefaults 魔法指令（进阶）

如果你不想改文件，也可以告诉 Conda：“忽略默认源”。你只需要执行下面这条命令：

conda config --add channels nodefaults

执行后，nodefaults 会被加到列表的最上面。Conda 看到这个词，就会强制忽略底部的 defaults。此时再次查看，你会发现 defaults 消失了，取而代之的是 - nodefaults。

💡 为什么必须去掉它？

因为中科大镜像站的 conda-forge 和 Anaconda 官方的 defaults 之间极其容易发生依赖冲突。如果你的列表里有 defaults，Conda 有时候会去访问境外的官方源，导致你安装包时超级卡顿，甚至报出 UnsatisfiableError（无法满足的依赖关系）。

去掉它之后，你以后的所有安装都会稳稳地走中科大镜像，速度飞快且不会冲突！

这是一个非常经典的 Conda 坑。不要慌，其实你的 nodefaults 已经生效了，只是 Conda 在“展示”上有点贼。

🧐 为什么它还在？

defaults 还在列表里，通常有两个原因：

  1. Conda 的显示机制：即便你加了 nodefaults，Conda 的 --show 命令有时候仍会硬塞一个 defaults 在最后展示出来（它认为默认源是系统底层的一部分）。但实际上在真正安装包、解析依赖时，nodefaults 会在最前面把 defaults 给“屏蔽”掉。
  2. 存在系统级的配置文件：因为你把 Miniconda 安装在了 /opt 目录下，可能系统级的全局配置文件 /opt/miniconda3/.condarc 里写死了 defaults。

🛠️ 彻底查明并干掉它（终极排查法）

我们直接找出是哪个文件在作祟。请在终端执行：

第一步：查看配置来源

conda config --show-sources

这个命令会列出所有生效的配置文件。你大概率会看到两个文件：

  • ==> /home/aikemi/.condarc <== （你的用户配置，里面有 nodefaults 和中科大源）
  • ==> /opt/miniconda3/.condarc <== （罪魁祸首大概率在这里，里面写了 defaults）

第二步：清理系统级配置（如果是上面的情况） 用 sudo 编辑那个系统级的配置文件：

sudo nano /opt/miniconda3/.condarc

如果里面看到了 - defaults，直接把它删掉，或者直接把整个文件清空（因为你的用户目录下已经配好了所有源）。保存退出（Ctrl+O, Enter, Ctrl+X）。

第三步：最后确认 再次运行：

conda config --show channels

这一次，那个烦人的 defaults 应该就彻底消失了。

💡 灵魂拷问：必须删吗？

不删也完全可以。

只要 conda config --show channels 的第一行是 nodefaults，你在后续使用 conda install 时，Conda 就会严格执行“绝不使用官方默认源”的指令。它就像一个警告牌，只要它在，后面的 defaults 就是个摆设。

如果你尝试了第一步和第二步，发现还是去不掉它，那就随它去吧。直接跑 conda install numpy 测试一下，只要下载地址全是 mirrors.ustc.edu.cn，没有卡顿，说明你的镜像源配置已经完美成功了！

Conda 安装软件“慢”通常分为两种情况：“卡在 Solving environment（解算环境）”，或者“下载速度慢”。

结合你的截图，你配置了 bioconda、conda-forge、r 和 main 四个频道。频道越多，依赖关系越复杂，Conda 默认的解算器就会越慢，因为它要把这四个频道的元数据全下载下来算一遍。

别急，用以下三个大招，立刻让它飞起来：

🚀 第一招：给 Conda 换上“超级引擎”（强烈推荐）

Conda 默认的解算器（Classic）极其老旧，算依赖能让人等到睡着。现在官方推荐使用 libmamba 解算器，速度能提升 10倍以上。

在终端（base环境）直接执行这两行命令：

# 1. 安装加速插件
conda install -n base conda-libmamba-solver -y

# 2. 设置为默认使用该引擎
conda config --set solver libmamba

(装好之后，你再运行 conda install jupyterlab，你会发现秒算完。)

🎯 第二招：精简频道，干掉“猪队友”

你装的是 JupyterLab，这纯粹是一个 Python 包。你的 bioconda 和 pkgs/r 频道在这里完全帮不上忙，还会拖慢计算速度。

直接指定只从 conda-forge 下载（因为 conda-forge 里的 jupyterlab 最新最全）。使用 -c 参数可以临时屏蔽其他频道：

conda install jupyterlab -c conda-forge

(加上 -c conda-forge 后，它就不去查其他杂七杂八的源了，速度极快)

🛑 第三招：如果还是慢，直接换 Pip！

既然你已经配好了中科大源，对于 JupyterLab 这类纯 Python 工具，直接用 pip 装往往比 conda 快十倍！ （反正它又不需要 C 语言编译的底层依赖）。

你可以按 Ctrl + C 强行终止现在的 conda install，然后直接用：

pip install jupyterlab -i https://pypi.mirrors.ustc.edu.cn/simple/

(秒下秒装，没有任何痛苦)

🔍 怎么判断到底卡在哪了？

如果你重新运行 conda install jupyterlab，注意看终端输出：

  • 如果一直显示 Solving environment: \ （一直在转圈）：说明卡在算依赖，用第一招。
  • 如果显示 Downloading and Extracting Packages 但进度条不动：说明下载慢，用第二招或第三招。

💡 友情提示：在跑 conda install 时，一定要看终端最上方输出的 Channels: 列表。如果看到里面有 defaults（之前跟你提过的那个），它可能偷偷去连国外服务器了，导致极其卡顿。

你看到的这个界面是 JupyterLab 的正常登录页面。它默认要求你输入一个叫做 Token（令牌） 的东西，或者是你自己设置的密码。

遇到这个界面不用慌，你有两种方法可以进去：

🔑 方法一：直接用 Token 登录（最快，当前就能进）

按照你截图里的提示，我们需要去 Ubuntu 终端里找这个 Token。

  1. 回到你的 Ubuntu 终端（或者 VS Code 里的终端）。
  2. 输入截图里提示的那行命令：
    jupyter server list
  3. 终端会输出类似下面这样的一长串内容： http://localhost:8888/?token=c8de56fa...
  4. 直接复制 token= 后面的那一长串字符（比如 c8de56fa...），粘贴到你截图里 “密码或令牌” 的输入框中，点击“登录”即可。

(注意：如果你关掉了 Jupyter 重新启动，这个 Token 会变。每次都要找很麻烦，所以推荐用方法二)

🔒 方法二：设置一个固定密码（强烈推荐，一劳永逸）

既然是你自己的服务器，肯定设个自己记得住的密码最方便。

第一步：在终端里设置密码 在 Ubuntu 终端里（确保你在安装了 jupyterlab 的环境里），运行：

jupyter server password

系统会提示你输入密码（输入时屏幕上不会显示字符，输完按回车），然后再输一次确认。设置成功后，它会在你的家目录下生成一个 jupyter_server_config.json 文件（或者 jupyter_notebook_config.json）。

第二步：用新密码登录 现在回到你的浏览器页面（截图界面），直接在顶部 “密码或令牌” 那里输入你刚才设置的密码，点击“登录”就能进去了。

第三步（关键补充）：以后怎么启动？ 因为你是通过远程 SSH 隧道访问的，下次启动 JupyterLab 时，需要加上允许所有 IP 访问的参数，否则你本地浏览器可能连不上：

jupyter lab --ip=0.0.0.0 --no-browser --port=8888

💡 如果你觉得每次都敲启动命令太麻烦

你可以直接修改 Jupyter 的配置文件，把“设置密码”、“允许所有IP访问”、“默认端口”全写死进去，以后只要敲一个 jupyter lab 就能启动。

在终端运行：

jupyter lab --generate-config

它会生成一个配置文件（通常路径在 ~/.jupyter/jupyter_lab_config.py），然后用 nano 打开它，找到这几行取消注释并修改：

c.ServerApp.ip = '0.0.0.0'
c.ServerApp.port = 8888
c.ServerApp.open_browser = False

保存后，以后直接在终端敲 jupyter lab 就能启动了，配合你设好的密码，简直是行云流水。快去试试找 Token 或者设密码吧！
