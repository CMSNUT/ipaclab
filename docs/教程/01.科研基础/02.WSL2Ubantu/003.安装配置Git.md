**毫无疑问，安装在 Ubuntu 里！**

这是因为你日常的代码编写（通过 VS Code 连进去）、计算运行、环境配置（Conda、Docker）全部都在 Ubuntu 中。**“代码在哪里，Git 就装在哪里”**是最合理的选择。

Windows Server 本身**不需要**安装 Git（除非你要在 Windows 下做开发，这显然不是你的需求）。

---

### 🐧 在 Ubuntu 中安装 Git 非常简单：

在你连上的 Ubuntu 终端里，执行以下两行命令即可：

```bash
sudo apt update
sudo apt install git -y
```

安装完成后，输入 `git --version` 能显示版本号就说明成功了。

---

### ⚙️ 装完必做的第一步：配置账号

在新电脑上装好 Git，第一件事就是告诉 Git 你是谁（对应你的 GitHub 或 Gitee 账号）：

```bash
git config --global user.name "你的名字或昵称"
git config --global user.email "你的邮箱@example.com"
```

---

### 💡 为什么不在 Windows 装？

1. **路径混乱**：如果代码在 Ubuntu（`/mnt/e/projects`），你在 Windows 下装 Git 去管理它，会涉及到极其复杂的跨系统路径映射（Windows 视角是 `E:\projects`），很容易出错。
2. **VS Code 联动**：当你用 VS Code 远程连入 Ubuntu 后，VS Code 左侧的“源代码管理”图标调用的就是 **Ubuntu 里的 Git**。你在 VS Code 里的终端（Terminal）敲 `git` 命令，也是在 Ubuntu 里跑。
3. **权限问题**：Linux 下的文件权限（可执行、读写）非常严格，Git 在 Linux 下能完美保留和追踪这些权限，跨到 Windows 下就容易丢失。

### 🔑 进阶建议：配置免密拉取代码（SSH Key）

如果你经常需要从 GitHub 或 Gitee 克隆（clone）代码，建议在 Ubuntu 里生成一下 SSH 密钥：

1. 在 Ubuntu 终端输入：
   ```bash
   ssh-keygen -t ed25519 -C "你的邮箱@example.com"
   ```
   一路狂按回车（不需要设密码）。
2. 查看并复制生成的公钥：
   ```bash
   cat ~/.ssh/id_ed25519.pub
   ```
3. 把终端里输出的一长串字符（以 `ssh-ed25519` 开头）复制，粘贴到你的 GitHub 账号设置（Settings -> SSH and GPG keys -> New SSH key）里。

这样以后你在 Ubuntu 里 `git clone git@github.com:xxx/xxx.git` 就不需要再输密码了。而且你之前的 `.ssh/config` 里配了 `github.com` 走 443 端口，这刚好能让你的操作非常顺畅！



**问到点子上了！你必须要在 Ubuntu 里面重新配置一遍。**

你之前在远程 Windows 的 `C:\Users\Administrator\.ssh\config` 里配置的 443 端口，**只对 Windows 本机的 SSH 客户端生效**（也就是让 VS Code 能连上服务器，或者让你在 Windows 命令行里能用）。

但是，你以后是用 **Ubuntu 里的 Git** 去执行 `git clone` 或 `git push`。**Ubuntu 里的 Git 调用的完全是 Ubuntu 自己的 SSH 客户端**，它根本看不到 Windows 上的配置文件。如果 Ubuntu 这边不配，一旦你的网络封锁了 22 端口，你在 Ubuntu 里拉取 GitHub 代码就会一直卡住或报错（`Connection timed out`）。

### 🛠️ 在 Ubuntu 中配置 GitHub 走 443 端口的步骤：

**第一步：确保在 Ubuntu 里存在 `.ssh` 目录**
在 Ubuntu 终端执行：
```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
```

**第二步：创建或编辑 Ubuntu 里的 config 文件**
```bash
nano ~/.ssh/config
```

**第三步：把那段代码贴进去**
在打开的空白文件里，粘贴你之前在 Windows 里看到的那段代码：
```ini
Host github.com
  Hostname ssh.github.com
  Port 443
  User git
  IdentitiesOnly yes
```
保存退出（`Ctrl+O`，回车，`Ctrl+X`）。

**第四步：测试连接**
在 Ubuntu 终端里输入：
```bash
ssh -T git@github.com
```
*   第一次连接会问你是否继续，输入 `yes` 回车。
*   如果看到类似 `Hi 你的用户名! You've successfully authenticated...` 的提示，就说明 443 通道打通了。
*   *(注意：如果提示 `Permission denied (publickey)`，那是因为你还没把 Ubuntu 的 SSH 公钥添加到 GitHub 账号里。你需要先执行 `ssh-keygen -t ed25519` 生成密钥，然后去 GitHub 网站添加公钥。)*

---

### 💡 为什么之前 VS Code 会报错连 `github.com`？

因为你当时在 VS Code 里选择连接目标时，**VS Code（运行在远程 Windows 上）读取了 Windows 的配置文件**，看到了 `Host github.com` 这一行，就误以为这是一个可以连接的远程开发服务器，所以你点它，它就去连 `github.com`，然后就报错了。

**总结一下：**
*   **Windows 上的配置**：服务于 VS Code 的 Remote-SSH 插件，让你能跨网络连进 Ubuntu。
*   **Ubuntu 上的配置**：服务于 Ubuntu 里的 Git，让你能在计算节点上顺畅地 pull/push GitHub 代码。

这两者是独立的，各配各的，互不干扰。你以后在 VS Code 里的 Ubuntu 终端敲 `git` 命令，用的就是 Ubuntu 里的这套配置。
