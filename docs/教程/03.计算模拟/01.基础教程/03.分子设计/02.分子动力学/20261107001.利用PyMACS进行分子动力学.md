### **`Hwloc support`**

- 主要用于识别双路 CPU 的 NUMA 架构（即哪根内存条插在哪颗 CPU 上）。
- **有什么影响**：因为你的服务器是**双路 CPU**（两颗物理芯片），没有 Hwloc，GROMACS 在把任务分配到 64 个核心时，可能无法做到“最优的本地内存读取”，跨 CPU 读取内存可能会产生一点点延迟。

```bash
sudo apt install libhwloc-dev
```

```bash
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
apply_ligandff_patch.py

把 1_AutomateGromacs.py 改造成 LigandFF 版本，输出 1_AutomateGromacs_ligandff.py。

用法:
    python apply_ligandff_patch.py
    python apply_ligandff_patch.py --src 1_AutomateGromacs.py --dst 1_AutomateGromacs_ligandff.py
    python apply_ligandff_patch.py --dry-run
"""

import argparse
import re
import sys
from pathlib import Path


# ============================================================
# 工具函数
# ============================================================

def fail(msg: str) -> None:
    print(f"\n❌ {msg}", file=sys.stderr)
    sys.exit(1)


def replace_once(text: str, old: str, new: str, label: str) -> str:
    n = text.count(old)
    if n == 0:
        fail(f"[{label}] 找不到要替换的片段")
    if n > 1:
        fail(f"[{label}] 片段出现 {n} 次，预期 1 次")
    return text.replace(old, new, 1)


def delete_once(text: str, old: str, label: str) -> str:
    return replace_once(text, old, "", label)


def replace_function_block(text: str, func_name: str, new_block: str, label: str = None) -> str:
    """从 `def func_name(` 到下一个顶层 `def ` / `class ` / 文件末尾，整块替换。"""
    label = label or func_name
    pattern = re.compile(
        rf"(?ms)^def {re.escape(func_name)}\(.*?(?=^def |^class |\Z)"
    )
    matches = list(pattern.finditer(text))
    if len(matches) != 1:
        fail(f"[{label}] 匹配到 {len(matches)} 个函数块，预期 1 个")
    m = matches[0]
    tail = text[m.end():]
    if not tail.startswith("\n"):
        tail = "\n" + tail
    return text[:m.start()] + new_block.rstrip("\n") + "\n\n\n" + tail.lstrip("\n")


def delete_function_block(text: str, func_name: str, label: str = None) -> str:
    """整块删除一个函数。"""
    label = label or func_name
    pattern = re.compile(
        rf"(?ms)^def {re.escape(func_name)}\(.*?(?=^def |^class |\Z)"
    )
    matches = list(pattern.finditer(text))
    if len(matches) != 1:
        fail(f"[{label}] 匹配到 {len(matches)} 个函数块，预期 1 个")
    m = matches[0]
    tail = text[m.end():]
    if not tail.startswith("\n"):
        tail = "\n" + tail
    return text[:m.start()] + tail.lstrip("\n")

def ensure_ligandff_env():
    """Locate the LigandFF executable."""
    exe = getattr(args, "ligandff_exec", None) or shutil.which("ligandff")

def extract_prm_from_ligandff_top(top_path, ligand_code, out_dir):
    """Extract [ atomtypes ] / [ nonbond_params ] / [ pairtypes ] from LigandFF .top -> .prm."""
    prm_path = os.path.join(out_dir, f"{ligand_code.lower()}.prm")
    prm_sections = {"atomtypes", "nonbond_params", "pairtypes"}

    if not os.path.exists(top_path):
        return None

    with open(top_path) as f:
        lines = f.readlines()

    out_lines = []
    mode = None
    for line in lines:
        s = line.strip().lower()
        if s.startswith("["):
            header = s.strip("[] ").strip()
            mode = "prm" if header in prm_sections else "other"
        if mode == "prm":
            out_lines.append(line)

    if not out_lines:
        return None

    with open(prm_path, "w") as f:
        f.writelines(out_lines)
    return prm_path


def validate_ligandff_outputs(ligand_code, directory):

def build_ligand_mol2_realtime(directory, ligand_code, source_complex_pdb):
    """
    Produce a LigandFF-ready MOL2 (all hydrogens, correct bond orders).

    Strategy:
      1) PyMOL headless (preferred): extract ligand + h_add + write MOL2
      2) OpenBabel fallback: extract HETATM+CONECT + -h -p 7.4 + write MOL2
      3) Normalise MOL2 names and force SUBSTRUCTURE block.

    LigandFF parameterisation happens later in prepare_component_topology().
    Returns the MOL2 path or None.
    """
    ligand_code = ligand_code.strip().upper()
    base = ligand_code.lower()

    complex_pdb = os.path.join(directory, source_complex_pdb)
    raw_pdb     = os.path.join(directory, f"{base}_raw.pdb")
    h_pdb       = os.path.join(directory, f"{base}_h.pdb")
    mol2        = os.path.join(directory, f"{ligand_code}.cgenff.mol2")

    if not os.path.exists(complex_pdb):
        print(f"❌ Complex PDB not found: {complex_pdb}")

    # ------------------------------------------------------------------

        pymol_stderr = os.path.join(directory, f"{ligand_code}.pymol.stderr.log")

reinitialize

select LIGSEL, {sel}

alter {ligand_code}, resn='{ligand_code}'

save {os.path.basename(h_pdb)}, {ligand_code}

        with open(pml_path, "w") as f:

            else:
                used_pymol = True
        else:
            print("⚠️ PyMOL path failed; falling back to OpenBabel.")
            print(f"   See logs: {os.path.basename(pymol_stdout)}, {os.path.basename(pymol_stderr)}")

    # 1b) OpenBabel fallback
    # ------------------------------------------------------------------
    if not used_pymol:
        if not extract_ligand_from_pdb(complex_pdb, ligand_code, raw_pdb):
            return None

### 修改脚本，放宽对 `.prm` 文件的检查

最直接有效的办法是修改 `1_AutomateGromacs_ligandff.py` 脚本，让它接受 LigandFF 风格的 `.prm` 文件。你只需要编辑脚本中的 `enforce_gromacs_prm_order` 函数，**移除或注释掉那个强制性的检查**即可。

**操作步骤：**

1. 打开你的 `1_AutomateGromacs_ligandff.py` 文件。

2. 找到 `enforce_gromacs_prm_order` 函数（大约在文件的第 500-550 行附近）。

3. 在该函数中，找到下面这段**检查并抛出错误**的代码：

   ```
   # sanity: ensure prm has at least something useful
   present = {sec.lower() for sec, _ in blocks}
   bonded_ok = any(s in present for s in ("bondtypes", "angletypes", "dihedraltypes"))
   if not bonded_ok:
       raise RuntimeError(f"❌ PRM has no bonded sections (bond/angle/dihedral). File: {prm_path}")
   ```

   

4. 将这几行**全部删除**，或者用 `#` 注释掉。

5. 保存文件，然后重新运行你的 PyMACS 命令即可。

**原理**：修改后，即使 `.prm` 文件里只有 `[ atomtypes ]`，脚本也不会再报错。因为 LigandFF 生成的 `.itp` 文件本身已经包含了配体所需的全部键合参数，GROMACS 在后续运行 `grompp` 时，会从 `.itp` 文件中正确读取这些信息。

def extract_prm_from_ligandff_top(top_path, ligand_code, out_dir):
    """Extract ONLY [ nonbond_params ] / [ pairtypes ] from LigandFF .top -> .prm.

    Why we deliberately drop atomtypes / moleculetype / atoms / bonds / ...

      - [ atomtypes ] is already fully present in charmm36.ff, so re-writing
        them causes "Atomtype ... was defined previously" warnings and risks
        silently overriding force-field parameters.
      - [ moleculetype ] / [ atoms ] / [ bonds ] / ... belong in <ligand>.itp,
        not in <ligand>.prm.  Writing them into .prm causes a fatal
        "moleculetype <LIG> is redefined" error at grompp time.

    This function ALWAYS overwrites <ligand>.prm, so stale content from
    previous runs is removed automatically.
    """
    prm_path = os.path.join(out_dir, f"{ligand_code.lower()}.prm")
    keep_sections = {"nonbond_params", "pairtypes"}

    if not os.path.exists(top_path):
        # Nothing to extract: write an empty-but-valid placeholder
        with open(prm_path, "w") as f:
            f.write(f"; LigandFF: no .top available for {ligand_code}; "

def enforce_gromacs_prm_order(prm_path):
    """Reorder a .prm into GROMACS-friendly order.

    LigandFF .prm files typically contain only [ nonbond_params ] / [ pairtypes ]
    and no bonded sections.  In that case there is nothing to reorder, so we
    just return instead of raising.
    """
    ORDER = [
        "atomtypes", "bondtypes", "angletypes", "dihedraltypes",
        "impropertypes", "nonbond_params",
    ]

    blocks = []
    current = None
    current_lines = []

    with open(prm_path) as f:
        for line in f:
            m = re.match(r"\[\s*([^\]]+?)\s*\]", line)
            if m:
                if current is not None:
                    blocks.append((current, current_lines))
                current = m.group(1).strip()
                current_lines = [line]
            else:
                if current is None:
                    blocks.append(("__preamble__", [line]))
                else:
                    current_lines.append(line)

    if current is not None:
        blocks.append((current, current_lines))

    present = {sec.lower() for sec, _ in blocks}
    bonded_ok = any(
        s in present for s in ("bondtypes", "angletypes", "dihedraltypes")
    )

              "skipping reorder.")
        return

        if sec == "__preamble__":
            out.extend(lines)

        for sec, lines in blocks:
            if sec.lower() == want:

            continue
        if sec.lower() not in ORDER:
            out.extend(lines)

        f.writelines(out)

    print(f"✅ PRM reordered safely (duplicates preserved): "
          f"{os.path.basename(prm_path)}")
'''.strip()

    if not tail.startswith("\n"):
        tail = "\n" + tail
    return text[:m.start()] + new_block.rstrip("\n") + "\n\n\n" + tail.lstrip("\n")

            continue

        if s.startswith("["):
            header = s.strip("[] ").strip()
            mode = "keep" if header in keep_sections else "drop"

        if mode == "keep":
            out_lines.append(line)

    with open(prm_path, "w") as f:
        if out_lines:
            f.writelines(out_lines)
        else:
            f.write(f"; LigandFF: no nonbond_params/pairtypes in .top for {ligand_code}; "
                    "using charmm36.ff defaults\n")

    if out_lines:
        print(f"✅ Extracted nonbond_params/pairtypes from "
              f"{os.path.basename(top_path)} -> {os.path.basename(prm_path)}")
    else:
        print(f"ℹ️ No nonbond_params/pairtypes in {os.path.basename(top_path)}; "
              f"empty placeholder .prm written for {ligand_code}.")

    return prm_path
```



**改动只有一处**：在读取每一行时，如果 `s.startswith("#include")`，直接 `continue` 跳过，不写入 `out_lines`。这样无论 `.top` 里有没有 `#include`，生成的 `.prm` 都不会再“反向 include” `.itp`。

WRAP_FUNC = '''def wrap_ligand_coords_to_continuous(pdb_in, pdb_out, crystal_pdb=None):
    """Wrap ligand coordinates across periodic boundaries using a BFS over atom connectivity.

    Uses CRYST1 from crystal_pdb (or pdb_in) as the periodic box.  Falls back to a
    bounding-box guess if no CRYST1 is found.  This fixes cryo-EM PDBs where the
    ligand is split across unit-cell corners, which otherwise crashes LigandFF's
    internal RDKit EmbedMolecule step and produces nonsense coordinates.
    """
    import numpy as np

    box = None
    candidates = [crystal_pdb, pdb_in] if crystal_pdb else [pdb_in]
    for path in candidates:
        if not path or not os.path.exists(path):
            continue
        with open(path) as fh:
            for line in fh:
                if line.startswith("CRYST1"):
                    box = np.array([
                        float(line[6:15]),
                        float(line[15:24]),
                        float(line[24:33]),
                    ])
                    break
        if box is not None:
            break

    lines = open(pdb_in).read().splitlines()
    atom_indices = []
    coords = []
    for i, line in enumerate(lines):
        if line.startswith(("ATOM", "HETATM")):
            atom_indices.append(i)
            coords.append([
                float(line[30:38]),
                float(line[38:46]),
                float(line[46:54]),
            ])
    if not coords:
        print(f"no atoms found in {pdb_in}, skipping wrap")
        return False
    coords = np.array(coords)

    span_before = coords.max(0) - coords.min(0)
    print(f"span before wrap ({os.path.basename(pdb_in)}): {span_before}")

    if box is None:
        print("no CRYST1 found; using bounding-box guess")
        box = span_before * 1.2 + 1.0

    n = len(coords)
    visited = np.zeros(n, dtype=bool)
    visited[0] = True
    new_coords = coords.copy()

    for _ in range(n - 1):
        best_i, best_j, best_d = None, None, np.inf
        for i in range(n):
            if visited[i]:
                continue
            d = np.linalg.norm(new_coords[i] - new_coords[visited], axis=1)
            j_local = int(d.argmin())
            if d[j_local] < best_d:
                best_d = d[j_local]
                best_i = i
                best_j = j_local
        for dim in range(3):
            delta = new_coords[best_i, dim] - new_coords[best_j, dim]
            while delta > box[dim] / 2:
                new_coords[best_i, dim] -= box[dim]
                delta = new_coords[best_i, dim] - new_coords[best_j, dim]
            while delta < -box[dim] / 2:
                new_coords[best_i, dim] += box[dim]
                delta = new_coords[best_i, dim] - new_coords[best_j, dim]
        visited[best_i] = True

    span_after = new_coords.max(0) - new_coords.min(0)
    print(f"span after wrap ({os.path.basename(pdb_in)}): {span_after}")

    out_lines = list(lines)
    for idx, atom_i in enumerate(atom_indices):
        old = out_lines[atom_i]
        c = new_coords[idx]
        out_lines[atom_i] = old[:30] + f"{c[0]:8.3f}{c[1]:8.3f}{c[2]:8.3f}" + old[54:]
    open(pdb_out, "w").write("\\n".join(out_lines) + "\\n")
    print(f"wrote {pdb_out}")
    return True
'''

                return None
            nH = count_h_in_pdb(h_pdb)

                return None

    print(f"Wrapping ligand coordinates using CRYST1 from {os.path.basename(crystal_pdb_path)}")

def strip_tabs(s: str) -> str:
    out = []
    for line in s.splitlines(keepends=True):
        stripped = line.lstrip(" \t")
        prefix = line[:len(line) - len(stripped)].replace("\t", "    ")
        out.append(prefix + stripped.replace("\t", "    "))
    return "".join(out)


def replace_func(text: str, name: str, new_block: str, anchor: str = None) -> str:
    """用正则定位并整块替换函数。如果函数不存在，可传入 anchor 在 anchor 之后插入。"""
    pattern = re.compile(
        rf"(?ms)^def {re.escape(name)}\(.*?(?=^def |^class |\Z)"
    )
    matches = list(pattern.finditer(text))
    if len(matches) == 1:
        m = matches[0]
        tail = text[m.end():]
        if not tail.startswith("\n"):
            tail = "\n" + tail
        return text[:m.start()] + new_block.rstrip("\n") + "\n\n\n" + tail.lstrip("\n")

    if len(matches) == 0 and anchor:
        # 在 anchor 定义之后插入
        pat_anchor = re.compile(
            rf"(?ms)^def {re.escape(anchor)}\(.*?(?=^def |^class |\Z)"
        )
        m = pat_anchor.search(text)
        if not m:
            raise RuntimeError(f"anchor {anchor}() not found")
        tail = text[m.end():]
        if not tail.startswith("\n"):
            tail = "\n" + tail
        return (
            text[:m.end()] + "\n\n"
            + new_block.rstrip("\n") + "\n\n\n"
            + tail.lstrip("\n")
        )

    raise RuntimeError(f"{name}: 匹配到 {len(matches)} 次，期望 1 次")


def main() -> None:
    ap = argparse.ArgumentParser()
    ap.add_argument("--src", default="1_AutomateGromacs_ligandff.py")
    args = ap.parse_args()

    src = Path(args.src)
    if not src.exists():
        sys.exit(f"找不到 {src}")

    text = src.read_text()
    print(f"读取 {src}（{len(text)} 字符）")

    # 1. 在 build_ligand_mol2_realtime 之前插入 wrap 函数
    wrap_block = strip_tabs(WRAP_FUNC)
    if "def wrap_ligand_coords_to_continuous" not in text:
        print("插入 wrap_ligand_coords_to_continuous ...")
        # 找 build_ligand_mol2_realtime 的位置，在它前面插
        pat = re.compile(r"(?m)^def build_ligand_mol2_realtime\(")
        m = pat.search(text)
        if not m:
            sys.exit("找不到 build_ligand_mol2_realtime，无法定位插入点")
        text = text[:m.start()] + wrap_block + "\n\n" + text[m.start():]
    else:
        print("wrap_ligand_coords_to_continuous 已存在，跳过插入")

    # 2. 整块替换 build_ligand_mol2_realtime
    print("替换 build_ligand_mol2_realtime ...")
    new_build = strip_tabs(NEW_BUILD_FUNC)
    text = replace_func(text, "build_ligand_mol2_realtime", new_build)

    # 3. 修改 prepare_component_topology 里的调用，传入 crystal_pdb
    print("修改 prepare_component_topology 中的调用点 ...")
    old_call = '''mol2_file = build_ligand_mol2_realtime(
                    directory,
                    component_code,
                    os.path.basename(template_raw_pdb),
                )'''

                    directory,
                    component_code,
                    os.path.basename(template_raw_pdb),
                    crystal_pdb=source_pdb_path,
                )'''
    if old_call in text:
        text = text.replace(old_call, new_call, 1)
        print("调用点已更新")
    elif "crystal_pdb=source_pdb_path" in text:
        print("调用点已含 crystal_pdb 参数，跳过")
    else:
        print("⚠️ 未找到标准调用点，请手动检查 prepare_component_topology 中 build_ligand_mol2_realtime 的调用")

    # 4. 全文件行首 Tab -> 4 空格（保险）
    fixed_lines = []
    fixed_count = 0
    for line in text.splitlines(keepends=True):
        stripped = line.lstrip(" \t")
        prefix = line[:len(line) - len(stripped)]
        if "\t" in prefix:
            fixed_count += 1
            prefix = prefix.replace("\t", "    ")
        fixed_lines.append(prefix + stripped)
    text = "".join(fixed_lines)
    if fixed_count:
        print(f"顺手修复 {fixed_count} 行行首 Tab")

    # 5. 语法检查
    try:
        compile(text, str(src), "exec")
        print("语法 OK")
    except SyntaxError as e:
        sys.exit(f"语法错误: {e}")

    src.write_text(text)
    print(f"写回 {src}（{len(text)} 字符）")
    print()
    print("✅ 完成。下一步：")
    print("   rm -f a1e*.pdb a1e*.gro a1e*.itp a1e*.top a1e*.prm a1e*.str a1e*.json A1E.cgenff.mol2")
    print("   重新运行 1_AutomateGromacs_ligandff.py")

## ⚠️ 如果 wrap 后 span 仍然很大

说明 9UWJ 的 CRYST1 不是配体跨边界的盒子（冷冻电镜有时 CRYST1 是重建盒，和原子坐标不匹配）。这种情况需要：

1. 手动检查 `9UWJ.pdb` 的 `CRYST1` 行
2. 如果 CRYST1 明显不合理，改用配体自身的 bounding box 作为 wrap 盒子（把 `crystal_pdb=None` 传进去，或临时改 wrap 函数）

把 wrap 的 `span before/after` 输出贴出来，我可以判断是 CRYST1 问题还是 BFS 问题。

## MD进度查询

### 🏃‍♂️ 如果模拟正在运行

查看 MD 模拟进度，需要区分模拟是**正在运行**还是**已经结束**。因为你之前使用了 `-quiet` 并重定向了输出，终端没有实时反馈，所以主要依靠文件来追踪。

#### **方法一：实时监控日志文件（最常用）**
这是最直接的方法。`mdrun` 会持续将步数、时间、性能等信息写入 `.log` 文件。
```bash
tail -f md.log
```
`-f` 参数会持续显示文件新增的内容，你可以实时看到当前进行到**第几步（Step）** 以及**模拟时间（Time）**。如果不需要持续刷新，直接用 `tail -n 50 md.log` 查看最后50行也可以。

#### **方法二：使用 `-v` 选项（针对未来运行）**
如果你**下次**启动新模拟时，在命令中加入 `-v`，`mdrun` 就会在终端动态打印当前步数和预计剩余时间（ETA）。
```bash
gmx mdrun -v -deffnm md
```

#### **方法三：检查 Checkpoint (.cpt) 文件**
`.cpt` 文件是模拟的“存档”，记录了精确的模拟进度。你可以查询它来了解最后保存的状态。
```bash
gmx check -f state.cpt
```
输出中会包含该检查点对应的**模拟步数（step）** 和**物理时间（ps）**。

#### **方法四：向进程发送 `USR1` 信号**
这是一个很巧妙的方法。向 `mdrun` 进程发送 `USR1` 信号，它会在不中断运行的情况下，**打印一次当前的进度和剩余时间**，效果如同临时加上 `-v` 选项。
```bash
# 先找到 mdrun 的进程 ID (PID)
pgrep -f "gmx mdrun"
# 假设 PID 是 12345，发送信号
kill -USR1 12345
```
然后你可以查看 `md.log` 或标准输出，会发现多了一行进度信息。



## 耗时统计与估计

模拟跑完后，总耗时和性能数据已经完整记录在日志文件里了。运行前的估算，则可以通过一次**短时间的试跑（Benchmark）** 来精确获得。

### 📜 运行后：如何查看真实总耗时

模拟结束后，所有性能统计都保存在 **`md.log` 文件末尾**的 `Performance` 和 `Real cycle and time accounting` 部分。

**1. 最直接：查看性能报告**

用 `tail` 命令查看 `md.log` 最后的内容，会看到类似下面的关键信息：

```bash
tail -n 50 md.log
```

报告的核心是这两行：

```
        (ns/day)    (hour/ns)
Performance:   3.964       6.054
```
*   **`ns/day`**：模拟吞吐量，表示一天能跑多少纳秒的轨迹。
*   **`hour/ns`**：其倒数，表示跑 **1 ns** 的模拟需要多少小时，这个指标对估算总时间非常直观。

**2. 计算实际总耗时**

如果想得到最精确的墙钟时间（Wall-clock time），可以从日志的起止时间戳来计算：
```bash
# 找到模拟开始和结束的时间戳
grep -E "Started mdrun|Finished mdrun" md.log
```
输出示例：
```
Started mdrun on rank 0 Wed Mar 11 00:00:00 2020
Finished mdrun on rank 0 Wed Mar 11 05:27:44 2020
```
将这两个时间相减，就是你本次模拟的真实总耗时（示例中约为 5小时27分）。

**3. 更详细的耗时分解**

`md.log` 末尾的 `Real cycle and time accounting` 表格会列出计算各部分（如非键相互作用、PME、通信等）所花费的**墙钟时间（Wall t）** 和**核心时间（Core t）**，有助于进一步了解时间花在了哪里。

---

### 📊 运行前：如何估算所需时间

由于无法凭空预测，最可靠的方法是**进行一次短时间的“预演”**。

**核心思路：先跑一个短任务，测出性能，再推算总时间。**

**1. 设置一个短时间的测试运行**

复制一份你正式的 `md.mdp` 文件（例如命名为 `bench.mdp`），将其中的 `nsteps` 修改为一个很小的值，比如 **2000步**（对于2 fs步长，即4 ps的模拟）。关键原则是**测试时长要足以让性能稳定下来**，避免启动开销的影响。

**2. 运行测试并获取性能数据**

用 `bench.mdp` 运行 `grompp` 和 `mdrun`：
```bash
gmx grompp -f bench.mdp -c your_start.gro -p topol.top -o bench.tpr
gmx mdrun -deffnm bench
```
模拟结束后，从生成的 `bench.log` 中获取 `ns/day` 或 `hour/ns` 值：
```bash
grep "Performance:" bench.log
```
假设你得到的性能是 **`hour/ns = 6.0`**。

**3. 推算总时间**

现在，用这个性能数据来估算你**正式模拟**（例如 `nsteps = 50000000`，即 **100 ns**）所需的时间：

```
预估总耗时 = 计划模拟时长 × hour/ns 值
           = 100 ns × 6.0 hour/ns
           = 600 小时 (约 25 天)
```

**4. 使用 `-v` 选项获取动态估计**

在运行正式模拟时，加上 **`-v`** 选项，`mdrun` 会定期在终端打印实时的进度和**预计剩余完成时间（ETA）**，这比任何事前估算都更准确，因为它基于当前的实际运行速度。
```bash
gmx mdrun -v -deffnm md -cpi state
```

---

### 💎 总结与提醒

*   **查看过去**：模拟结束后，`md.log` 里的 **`Performance`** 段和 **`Started/Finished mdrun`** 时间戳，能告诉你真实的总耗时和平均性能。
*   **预测未来**：通过一次**短时间的 Benchmark 试跑**，从生成的日志中获取 `hour/ns` 值，再乘以你计划的总模拟时长，是进行资源申请和时间规划的标准做法。
*   请注意，短时间 Benchmark 得到的性能**通常会优于**长时间生产模拟的平均性能，因为它没有包含后期的负载均衡调整等开销，所以据此估算的时间可视为一个**乐观的底线**。



### 🔎 验证当前计划生产长度`.tpr`



```

```

总生产时间计算公式如下：

```text
time (ns) = nsteps × delta_t(ps) / 1000
```

### 💡 估算剩余时间的小技巧

如果你想知道“大概还要多久”，可以结合日志文件自己算一下。
1.  在 `md.log` 里找到 `Started mdrun on ...` 这行，记下**开始时间**。
2.  找到最近一次记录，记下**当前步数**和**时间戳**。
3.  用 `(当前时间 - 开始时间) / 当前步数` 得到每步平均耗时。
4.  用 `(总步数 - 当前步数) * 每步平均耗时`，就能估算出剩余时间。

如果你的模拟是在后台或集群上运行，最稳妥的方式是结合 `tail -f md.log` 观察动态，并定期用 `gmx check -f state.cpt` 确认存档点，这样对进度就完全掌握了。

## 🚀 移动最佳方案

`tar + pigz 压缩 → 移动 → 校验 → 删源`

```bash
cd ~/projects/mdruns

# 1. 压缩（pigz 多线程，比 gzip 快数倍；没装则回退 gzip）
if command -v pigz >/dev/null 2>&1; then
    tar -I pigz -cf ligandff_test.tar.gz ligandff_test/
else
    tar -czf ligandff_test.tar.gz ligandff_test/
fi

# 2. 校验压缩包完整性
tar -tzf ligandff_test.tar.gz > /dev/null && echo "✅ tar 完整性 OK"

# 3. 建目标目录并移动
mkdir -p /mnt/e/projects/mdruns
mv ligandff_test.tar.gz /mnt/e/projects/mdruns/

# 4. 核对大小（两边应完全一致）
ls -lh /mnt/e/projects/mdruns/ligandff_test.tar.gz

# 5. 确认无误后删源
rm -rf ~/projects/mdruns/ligandff_test
```

---

### 📦 压缩选项说明

| 选项                | 作用                           | 何时用                     |
| ------------------- | ------------------------------ | -------------------------- |
| `tar -I pigz -cf`   | 多线程 gzip，**最快**          | 有 `pigz` 时首选           |
| `tar -czf`          | 单线程 gzip，兼容性最好        | 没装 `pigz` 时             |
| `tar -cf`（不压缩） | 最快，但文件最大               | 磁盘空间充足且追求极致速度 |
| `tar --zstd -cf`    | zstd 压缩，速度/压缩率平衡最佳 | 系统有 `zstd` 时也推荐     |

**MD 输出目录的压缩率参考**：

- `.xtc` / `.trr`（二进制轨迹）：压缩率约 **50–70%**（已压缩过，收益有限）
- `.edr` / `.log` / `.itp` / 分析 CSV：压缩率 **80–95%**（文本，收益极大）

整体预计压缩到原大小的 **40–60%**。

### 🔁 如果 WSL 磁盘还是不够

WSL 的虚拟磁盘（`ext4.vhdx`）**不会自动缩小**。即使你在 Ubuntu 里删了 50 GB，Windows 侧 `ext4.vhdx` 文件大小可能不变。需要手动压缩：

#### Windows PowerShell（管理员）

```powershell
# 1. 关闭 WSL
wsl --shutdown

# 2. 找到 vhdx 路径
# 通常在 C:\Users\<你的用户名>\AppData\Local\Packages\CanonicalGroupLimited.Ubuntu*\LocalState\ext4.vhdx

# 3. 用 diskpart 压缩
diskpart
# 进入 diskpart 后：
select vdisk file="C:\Users\<用户名>\AppData\Local\Packages\CanonicalGroupLimited.Ubuntu_79rhkp1fndgsc\LocalState\ext4.vhdx"
attach vdisk readonly
compact vdisk
detach vdisk
exit
```

或更简单的 PowerShell 命令（Windows 11）：

```powershell
Optimize-VHD -Path "C:\path\to\ext4.vhdx" -Mode Full
```

这会真正把 Windows 侧的 `.vhdx` 文件缩小，回收物理磁盘空间。

1. **WSL 内清理**（apt / conda / pip / journal / tmp）→ 释放 Ubuntu 内部空间

3. **WSL 仍不够** → Windows 侧 `compact vdisk` 压缩 `.vhdx` → 真正归还给 Windows

先执行 1 和 2，把 `df -h /` 清理前后的输出贴出来，可以判断是否需要做第 3 步。
