以下是整合全部修订后的最终项目规划。品牌名 **ACStudio**（中文 **析作室**），定位为覆盖化学分析与仪器分析全流程的智能互动实验台，PC 端优先适配 Windows / macOS / Linux。

---

## 一、项目定位与命名

**品牌**：ACStudio / 析作室
**副标题**：化学分析与仪器分析智能互动实验台
**覆盖范围**：化学分析（滴定、重量、样品制备）+ 仪器分析（UV-Vis、分子荧光、原子光谱、色谱、电化学）
**目标用户**：本科生，配合课堂与实验教学
**分发形态**：三平台桌面应用（Windows `.exe`、macOS `.app/.dmg`、Linux `.bin/AppImage`），离线运行，内置授权与加密

**授权文件**：`ACStudio.lic`（Ed25519 签名）
**安装包命名**：`ACStudio-Setup-<version>-<platform>`
**子模块前缀**：`ACStudio Titra` / `Grav` / `Prep` / `UVVis` / `FLS` / `Atom` / `Chroma` / `Electro`


## 二、技术栈

| 层次 | 选型 | 说明 |
|---|---|---|
| UI | **PySide6** | LGPL，可闭源分发；三平台原生支持 |
| 图形 | **Plotly** 嵌入 `QWebEngineView` | 保留悬停、缩放、选点交互；必要时用 Matplotlib Qt 后端做轻量替代 |
| 化学计算 | `pHcalc`（酸碱/配位滴定）+ `efta`（萃取）+ NumPy/SciPy + 自定义求解器 | 纯 Python，三平台一致 |
| 仪器分析计算 | 自定义峰形模拟（高斯/洛伦兹/EMG）、标准曲线拟合、内标法/标准加入法、能斯特方程 | 轻量，NumPy 足够 |
| 代码保护 | **PyArmor**（关键模块混淆与完整性校验）+ **Nuitka**（编译为原生机器码） | 三平台分别加密与编译 |
| 打包 | **Nuitka**（`--standalone` 或 `--onefile`，`--plugin-enable=pyside6`） | macOS 固定产出 `.app` bundle |
| 授权 | **Ed25519 离线签名** + 跨平台机器码 | 客户端仅内置公钥；私钥离线保管 |
| CI/CD | **GitHub Actions 矩阵构建** + Nuitka-Action | 三平台并行 |


## 三、模块结构（3 + 5）

### 化学分析模块

| 模块 | 覆盖内容 | 可视化核心 | 计算依赖 |
|---|---|---|---|
| **Titra** | 酸碱/配位/氧化还原/沉淀滴定 | 滴定曲线、分布分数、突跃范围、终点误差 | `pHcalc` + 自定义能斯特/\(K_{sp}\) 函数 |
| **Grav** | 沉淀重量分析 | 称量流程、换算因数、误差传播 | 自定义函数 |
| **Prep** | 样品制备：萃取分离、离子交换、沉淀分离、富集、净化，含简化固相萃取模型 | 萃取级数剖面、分配比曲线、富集倍数、净化效率 | `efta` + 简化 SPE 模型 |

### 仪器分析模块

| 模块 | 覆盖内容 | 可视化核心 | 计算依赖 |
|---|---|---|---|
| **UVVis** | 紫外-可见吸收光谱 | 吸收光谱、标准曲线、比尔定律偏离、仪器参数影响 | 峰形模拟 + `polyfit` |
| **FLS** | 分子荧光光谱 | 激发/发射双扫描、强度—浓度曲线、内滤效应、猝灭 | 峰形模拟 + 非线性拟合 |
| **Atom** | AAS、AES、原子荧光 | 谱线强度—浓度曲线、标准加入法外推、干扰效应 | 自定义线性/非线性拟合 |
| **Chroma** | 气相色谱、液相色谱 | 色谱图、保留时间、峰面积手动/自动积分、内标法/归一化法 | EMG/高斯峰形模拟 + 积分算法 |
| **Electro** | 电位分析、伏安法、电导分析 | 电位—体积曲线、伏安图、标准加入法 | 能斯特方程 + 自定义函数 |

`Electro` 作为第三阶段的可选增量；`Atom` 和 `Chroma` 纳入首版。`Prep` 放在化学分析分区末尾，在视觉与教学上承担“从样品到测定”的衔接角色。

**UI 一级导航**：两个分区——“化学分析”（Titra / Grav / Prep）与“仪器分析”（UVVis / FLS / Atom / Chroma / Electro），与教材章节划分一致。


## 四、物理包结构

```
acstudio/
├── ac_core/                  # 计算引擎，零 UI 依赖
│   ├── chemical/
│   │   ├── titration.py      # Titra
│   │   ├── gravimetry.py     # Grav
│   │   └── preparation.py    # Prep
│   ├── instrumental/
│   │   ├── uvvis.py          # UVVis
│   │   ├── fls.py            # FLS
│   │   ├── atom.py           # Atom
│   │   ├── chroma.py         # Chroma
│   │   ├── electro.py        # Electro
│   │   └── spectra_common.py # 峰形模拟与拟合共用
│   └── common/               # 标准曲线拟合、误差传播等跨模块工具
├── ac_auth/                  # 授权模块，独立于业务层
│   ├── machine_id.py         # 三平台机器码
│   ├── license_verify.py     # Ed25519 验签、到期检查、回拨检测
│   └── guard.py              # 主入口前置检查
├── ac_ui/                    # PySide6 界面层
│   ├── main_window.py
│   ├── modules/              # 各模块页面
│   ├── widgets/              # 参数控件、图形容器、任务卡面板
│   └── resources/            # 图标、样式、翻译
├── ac_build/                 # 构建脚本
│   ├── nuitka_config.py
│   ├── pyarmor_config.py
│   └── ci_matrix.yml
└── main.py                   # 入口：先调 ac_auth，再启动 ac_ui
```

**边界原则**：`ac_core` 不导入 PySide6 或 Plotly；`ac_auth` 不导入 `ac_core`；`ac_ui` 通过信号—槽调用 `ac_core`。这个边界是后续移动端或云端复用计算核心的前提。


## 五、分阶段实施路线

### 第一阶段：垂直切片验证（约 2—3 周）

- 完成 `ac_core/chemical/titration.py` 的酸碱滴定部分（`pHcalc` 生成曲线与分布分数）。
- 在 PySide6 中搭建最小主窗口：三个滑块（浓度、\(K_a\)、滴定体积）+ Plotly 嵌入图 + 计量点/突跃范围输出。
- 在 **Windows** 上跑通“参数 → 计算 → 绘图 → 数值反馈”闭环。
- 不接授权、不做 PyArmor/Nuitka，只验证教学交互逻辑。

**交付判据**：拖动滑块时曲线实时更新，数值反馈正确，交互延迟可接受。

### 第二阶段：化学分析全模块 + 仪器分析首版（约 4—5 周）

- 横向补齐 `Grav`、`Prep`，每个模块包含参数控件、互动图、引导性任务卡。
- 并行推进仪器分析首批模块：
  - `UVVis`：吸收光谱 + 标准曲线 + 高浓度偏离线性。
  - `FLS`：激发/发射双扫描 + 强度—浓度曲线 + 内滤效应。
  - `Atom`：谱线强度—浓度曲线 + 标准加入法外推。
  - `Chroma`：模拟色谱图 + 手动选峰积分 vs 自动积分对比。
- 抽取 `spectra_common.py`，供 `UVVis`、`FLS`、`Atom` 共用峰形与拟合函数。
- 在 macOS 和 Linux 上验证 UI 渲染一致性（字体、高 DPI、`QWebEngineView` 路径）。
- **新增技术验证**：
  - “色谱峰手动选点积分”最小原型，验证 Plotly `selectedpoints`/`lasso` 在 `QWebEngineView` 中的流畅度。
  - `FLS` 双波长扫描交互原型。
  - `Prep` 与 `UVVis` 的衔接任务卡（“先富集再测定 vs 直接测定”）。

**交付判据**：8 个模块中至少 6 个可用（`Electro` 可延后），三平台 UI 无阻断性问题，两类新增交互原型通过验证。

### 第三阶段：授权、加密与 Electro（约 3 周）

- 实现 `ac_auth`：三平台机器码生成、Ed25519 验签、到期检查、本地时钟回拨检测。
- 主入口 `main.py` 最先调用授权检查，未通过则弹出激活窗口并退出。
- 接入 PyArmor 对 `ac_core` 与 `ac_auth` 加密，验证加密后计算功能正常。
- 完成 `Electro` 模块（能斯特方程、电位—体积曲线、标准加入法）。
- 仍在开发机上以 Python 脚本运行，不急于 Nuitka。

**交付判据**：无有效 `.lic` 时程序拒绝进入主界面；有效授权下全部模块功能正常；加密后自检通过。

### 第四阶段：三平台 CI 构建与发布（约 2—3 周）

- 配置 GitHub Actions 矩阵：`windows-latest` / `macos-latest` / `ubuntu-latest` 并行执行 PyArmor（指定当前平台）→ Nuitka 编译 → 产物收集。
- 产物形态：Windows `.exe`；Linux `.bin`（可选封装 AppImage）；macOS `.app` 打包为 `.dmg`。
- 每平台冒烟测试：启动 → 授权校验 → 主界面 → 至少两个模块可交互 → 退出。
- **先让 Windows 产物稳定**，再依次合并 macOS 和 Linux 构建分支。
- macOS 若面向非技术用户分发，需纳入 Apple Developer 签名与公证流程。

**交付判据**：三平台产物均可启动、授权、进入主界面并完成核心交互。


## 六、跨平台构建要点

**三平台独立构建**。PyArmor 的运行文件含平台相关动态库，Nuitka 为本地编译，**不能交叉编译**。CI 矩阵中每个 runner 显式指定 PyArmor 平台（`windows.x86_64` / `linux.x86_64` / `darwin.x86_64`）。

**产物形态差异**。macOS 即使 `--onefile` 也产出 `.app` bundle，构建脚本需分支处理；Linux 需注意 glibc 兼容性，建议在较旧 Ubuntu LTS 上构建或提供 AppImage。

**构建顺序**。`PyArmor 加密 ac_core/ac_auth` → `Nuitka 编译入口`。锁定两者版本并在 CI 中加“加密后运行计算自检”步骤，防止版本升级导致加密产物异常。

**体积控制**。PySide6 + NumPy/SciPy + Plotly 的 `--onefile` 产物可能在 80—150MB 量级。第二阶段末期根据实际体积决定是否改用 `--standalone` 目录分发，或评估能否削减 SciPy 依赖。


## 七、关键风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| PyArmor 与 Nuitka 版本耦合 | 加密产物运行异常 | 锁定已验证版本组合；CI 加自检步骤 |
| 色谱/FLS 图形交互在 `QWebEngineView` 中不流畅 | 仪器分析互动体验下降 | 第二阶段早期做最小原型验证；必要时改用 Matplotlib Qt 后端或自定义 Qt 绘图 |
| macOS Gatekeeper 拦截 | 非技术用户无法直接打开 | 纳入 Apple Developer 签名与公证流程 |
| Windows 杀毒误报 | 用户信任度下降 | `--windows-disable-console`；发布页提供哈希；有条件时做代码签名 |
| 离线日期控制可被绕过 | 授权日期约束减弱 | 本地回拨检测提高门槛；预留可选在线校验端点 |
| 产物体积过大 | 分发与下载体验差 | 评估 `--standalone` 分发；削减非必要依赖 |


## 八、教学层配套

每个模块除交互页面外，配一张**引导性任务卡**，把“操作”转化为“观察—归纳”：

- **Titra**：固定 \(c\) 和 \(K_a\)，只改变滴定剂浓度，突跃范围如何变化？
- **Grav**：换算因数变化时，称量误差如何传播到最终结果？
- **Prep**：同一份水样，先做萃取富集再测 UV-Vis，与直接测定相比，标准曲线和检出限如何变化？
- **UVVis**：高浓度下标准曲线为何弯曲？如何判断偏离比尔定律？
- **FLS**：切换激发/发射扫描模式，峰位与强度如何对应？内滤效应何时显著？
- **Atom**：标准加入法的外推截距为什么能反推基体中的浓度？
- **Chroma**：改变流速，保留时间与分离度如何变化？手动积分与自动积分的峰面积差异从何而来？
- **Electro**：标准加入法的电位—体积曲线斜率由什么决定？

关键模块保留可展开的“查看计算过程/公式”区域，避免黑箱化。`Prep` 的衔接任务卡与 `UVVis` 呼应，使“样品制备”不只是独立章节，而是与仪器分析形成教学闭环。
