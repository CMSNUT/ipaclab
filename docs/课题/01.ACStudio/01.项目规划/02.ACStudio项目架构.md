# ACStudio 项目架构文档

**产品名**：ACStudio / 析作室
**定位**：化学分析与仪器分析智能互动实验台
**版本**：v1.0 架构基线
**形态**：Windows / macOS / Linux 离线桌面应用，内置授权与预置用户数据，预留在线维护接口

---

## 1. 分层架构与边界原则

```
┌─────────────────────────────────────────────────────┐
│  ac_ui        界面层（PySide6）                      │
│  主窗口 / 模块导航 / 学习·巩固·拓展 / 用户面板        │
├─────────────────────────────────────────────────────┤
│  data_manager / model_manager / services            │
│  仓储接口、数据访问、模型配置、学习记录、报告         │
├─────────────────────────────────────────────────────┤
│  ac_core      计算引擎（纯 Python，零 UI 依赖）       │
│  chemical/    仪器分析/     common/                   │
├─────────────────────────────────────────────────────┤
│  ac_auth      授权与安全（独立于业务层）              │
│  机器码 / Ed25519 验签 / 预置数据包解锁 / 回拨检测   │
└─────────────────────────────────────────────────────┘
```

**边界原则（强制）** ：

- `ac_core` 不导入 PySide6、Plotly、SQLite 或任何 UI/存储库。
- `ac_auth` 不导入 `ac_core` 与 `ac_ui`，仅依赖密码学库与机器指纹库。
- `ac_ui` 通过 `services` 层调用 `ac_core` 与 `data_manager`，不直接访问 SQLite。
- `main.py` 入口顺序固定：`ac_auth.guard` → `data_manager.init` → `ac_ui.launch`。

## 3. 各层职责与关键接口

### 3.1 `ac_core`：计算引擎

对外只暴露纯函数与 dataclass，输入参数 → 返回 NumPy 数组或数据对象。示例接口：

```python
# ac_core/chemical/titration.py
def acid_base_curve(c_analyte, ka_list, v_analyte, c_titrant, v_range) -> TitrationCurve: ...
def distribution_fraction(ka_list, ph_range) -> DistributionResult: ...
def equivalence_point(curve: TitrationCurve) -> EquivalenceInfo: ...

# ac_core/instrumental/uvvis.py
def absorption_spectrum(concentration, epsilon, wavelength_range) -> Spectrum: ...
def standard_curve(points: list[CalPoint]) -> CalibrationResult: ...
def check_beer_deviation(curve: CalibrationResult) -> DeviationReport: ...

# ac_core/instrumental/chroma.py
def simulate_chromatogram(peaks: list[PeakParam], time_range) -> Chromatogram: ...
def integrate_peaks(chromatogram, selected_ranges) -> IntegrationResult: ...
```

所有模块遵循同一约定：`*_models.py` 定义输入输出数据类，计算函数无副作用，便于单元测试与后续移动端/云端复用。

### 3.2 `ac_auth`：授权与安全

`guard.run()` 是入口第一道关卡，执行顺序：

1. 读取并验证 `.lic`：Ed25519 验签 → 机器码比对 → 到期检查 → 时钟回拨检测。
2. 解锁预置数据包：验证 `users.sig` → 解封装 AES 密钥 → 解密 `users.enc` → 比对版本号。
3. 返回 `AuthContext`（含用户数据版本、授权到期日、机器码哈希），供 `data_manager.init` 使用。

失败时抛出明确异常类型（`LicenseExpired`、`LicenseMismatch`、`DataPackTampered`），由 UI 层弹出对应提示后退出。

### 3.3 `services`：业务服务层

UI 不直接调用仓储或计算函数，而是通过 services 组合：

```python
class AuthService:
    def login(self, student_no: str, password: str) -> Session | None: ...
    def current_user(self) -> User | None: ...
    def check_permission(self, feature: str) -> bool: ...

class QuizService:
    def get_questions(self, module: str, level: str) -> list[Question]: ...
    def submit(self, session: Session, question_id: str, answer: str) -> GradeResult: ...
    def wrong_book(self, session: Session) -> list[WrongItem]: ...
```

这一层是未来切换在线仓储的唯一改动点。

### 3.4 `data_manager`：仓储与存储

- 抽象接口在 `repositories/base.py`，当前只有 Local 实现；`remote_stub.py` 保留在线契约，不参与运行。
- SQLite 数据库位于用户目录：Windows `%APPDATA%/ACStudio/acstudio.db`，macOS `~/Library/Application Support/ACStudio/`，Linux `~/.local/share/ACStudio/`。
- `schema.sql` 中的静态表（`users`/`classes`/`role_permissions`）与动态表（`learning_progress`/`quiz_answers`/`experiment_records`/`reports`）同库；预置包更新时只覆盖静态表，动态表保留。
- 覆盖静态表时显式保留 `password_hash` 与 `password_changed` 列。

### 3.5 `ac_ui`：界面层

- 主窗口采用三栏布局：左侧导航、中间模块工作区（学习/巩固/拓展）、右侧用户面板（头像、学号、姓名、班级、北京时间、星期、学习进度、退出）。
- 北京时间使用 `datetime.now(ZoneInfo("Asia/Shanghai"))`，格式“2025年11月2日 星期日 14:30:25”，每秒刷新，不依赖系统时区。
- 图形统一通过 `widgets/plotly_view.py` 嵌入 `QWebEngineView`；若某模块交互验证不通过，替换为 Matplotlib Qt 后端，接口不变。
- 菜单栏：文件（新建/打开/保存/导入/导出/最近）、编辑、视图（主题/演示模式）、工具（计算器/常数/换算/截图）、帮助（手册/快捷键/关于/版权）。

## 4. 数据与安全设计

### 4.1 预置数据包

| 文件 | 内容 | 保护 |
|---|---|---|
| `users.enc` | SQLite 字节流 | AES-256-GCM |
| `users.sig` | 对 `users.enc` 哈希的签名 | Ed25519 私钥签发 |
| `manifest.json` | 数据版本、签发时间、哈希 | 明文，供版本比对 |

**AES 密钥保护**：首版采用“密钥硬编码于 `ac_auth`，由 PyArmor 加密保护”；第三阶段可选升级为“密钥封装文件 + 公钥解封装”，表结构与解锁流程不变。

**版本更新**：新预置包携带更高 `data_pack_version`，启动时覆盖静态表并保留动态表与已修改密码。

### 4.2 授权文件 `.lic`

编码内容：账号标识、到期日期、绑定机器码哈希、签发时间。客户端仅内置 Ed25519 公钥，私钥离线保管于发行方。日期控制依赖到期时间 + 本地回拨检测；预留在线校验端点接口，默认关闭。

### 4.3 本地数据防篡改

登录时比对本地 `users` 表的关键字段（`student_no`/`name`/`class_id`/`role`）与预置包解锁后的数据是否一致；不一致则拒绝登录并提示数据异常。密码以 argon2 哈希存储，任何环节不存明文。

### 4.4 在线维护预留

`config.json`（用户目录）：

```json
{
  "mode": "offline",
  "server": {
    "base_url": "",
    "api_key": "",
    "sync_enabled": false,
    "sync_interval_minutes": 30
  },
  "data_pack_version": "2025.11.01"
}
```

预留 API 契约（写入 `data_manager/sync/sync_service.py` 注释，不实现）：

- `POST /auth/login`
- `GET /users?since=<timestamp>`
- `POST /progress/sync`

冲突策略：用户与权限以服务端为权威源；学习记录以最后写入时间合并。启用时只需切换 `mode` 为 `hybrid` 并实现 `SyncService`，业务层与表结构不变。

## 5. 构建与发布

### 5.1 构建链

```
PyArmor 加密 ac_core + ac_auth（指定当前平台）
        ↓
Nuitka 编译 main.py（--plugin-enable=pyside6）
        ↓
产物：Windows .exe / Linux .bin / macOS .app → .dmg
```

### 5.2 CI 矩阵

GitHub Actions 三平台并行，每个 runner 执行：安装依赖 → 单元测试 → PyArmor（显式指定 `windows.x86_64` / `linux.x86_64` / `darwin.x86_64`）→ Nuitka → 冒烟测试 → 上传产物。锁定 PyArmor 与 Nuitka 版本，并在 CI 中加入“加密后运行计算自检”。

### 5.3 平台差异

- macOS 固定产出 `.app`，需 Apple Developer 签名与公证。
- Linux 在较旧 Ubuntu LTS 构建或提供 AppImage，规避 glibc 兼容问题。
- Windows 使用 `--windows-disable-console`，发布页提供哈希值，有条件时做代码签名。

本架构文档与前述项目规划一致：`ac_core` 保持零 UI 依赖，`ac_auth` 独立前置，`services` 作为未来在线切换的唯一改动点，预置数据包与动态数据分库共存。后续任何功能增补应优先落在既有层内，避免穿透边界。
