## 1. 基线选择说明

Python 版本选择 **3.12**，基于以下约束：

- **PyArmor 8/9** 对 3.12 及以上版本的支持在 9.0.x 系列中逐步完善，3.12 是当前最稳妥的“新版本”基线。
- **Nuitka** 官方声明兼容 Python 2.6、2.7、3.4—3.14，3.12 在支持范围内。
- **pHcalc** 依赖 NumPy ≥ 1.10、SciPy ≥ 0.17，对 Python 3.12 无额外限制。
- **efta** 要求 Python 3.10+，3.12 满足。
- **PySide6** 从 6.4.3 起可在 conda 环境内使用，Python 3.12 有对应的 wheel 或 conda-forge 包。

若后续 PyArmor 对 3.13 的支持在 CI 中验证通过，可再升版本；首版基线锁定 3.12。

## 2. 前置：安装 Anaconda 或 Miniconda

**Windows**：从 Anaconda 官网下载安装包，安装时勾选“Add to PATH”或使用 Anaconda Prompt。

**macOS**：推荐通过 Homebrew 安装 Miniconda，或下载 `.pkg` 安装包。安装后确认 `conda` 在终端可用：

```bash
conda --version
```

**Linux**：下载 Miniconda 安装脚本并执行：

```bash
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash Miniconda3-latest-Linux-x86_64.sh
source ~/.bashrc
conda --version
```

## 4. 安装运行时依赖

以下命令在 `acstudio` 环境内执行。**优先使用 pip**，因为部分包（如 `efta`）在 conda 主通道中可能不存在或版本滞后；PySide6 可通过 conda-forge 安装，但 pip 版本与 PyArmor/Nuitka 的兼容性在社区中验证更多。

### 4.1 核心 UI 与图形

```bash
pip install PySide6
pip install plotly
```

**说明**：`PySide6` 包含 Qt 运行时与 `QWebEngineView` 所需组件。安装后需验证 `PySide6.QtWebEngineWidgets` 可导入。

### 4.2 化学与数值计算

```bash
pip install numpy scipy
pip install pHcalc
pip install efta
```

`pHcalc` 的 pip 包名为 `pHcalc`（大小写不敏感但建议按官方写法）；`efta` 会自动安装 NumPy、SciPy、Matplotlib。

### 4.3 密码学与密码哈希

```bash
pip install cryptography
pip install argon2-cffi
```

`cryptography` 提供 Ed25519 签名验证与 AES-GCM 解密所需的底层原语；`argon2-cffi` 用于预置数据包中密码的 argon2 哈希验证。

### 4.4 机器码与系统信息

```bash
pip install machineid
```

若该包在目标平台不可用，可在 `ac_auth/machine_id.py` 中按平台自行实现（Windows 读 WMI/`MachineGuid`，macOS 读 `IOPlatformUUID`，Linux 读 `/etc/machine-id`）。

### 4.5 数据与 Excel 导入导出

```bash
pip install openpyxl
```

用于 `.xlsx` 实验数据导入导出。SQLite 与 `zoneinfo` 是 Python 标准库，不需要额外安装。

### 4.6 一次性安装命令（推荐）

建议在项目根目录维护 `requirements-runtime.txt`：

```
PySide6
plotly
numpy
scipy
pHcalc
efta
cryptography
argon2-cffi
machineid
openpyxl
```

安装：

```bash
pip install -r requirements-runtime.txt
```

## 6. 三平台 C 编译器准备（Nuitka 编译必需）

Nuitka 将 Python 编译为 C 再生成机器码，**每个平台都需要可用的 C 编译器**。这一步不发生在日常开发阶段，但在首次尝试 Nuitka 编译前必须完成。

### 6.1 Windows

Nuitka 在 Windows 上可以使用 **MinGW-w64** 或 **MSVC**。推荐让 Nuitka 自动下载 MinGW64（基于 gcc 11.2 或更高）。

**方式 A（推荐，自动）** ：首次运行 Nuitka 时，若未检测到编译器，Nuitka 会提示并尝试自动下载 winlibs 的 MinGW64。按提示操作即可。

**方式 B（手动，MSVC）** ：安装 **Visual Studio Build Tools**，勾选“使用 C++ 的桌面开发”工作负载，包含 MSVC 与 Windows SDK。Nuitka 会自动检测 MSVC。

**验证**：

```bash
gcc --version
# 或 cl
```

### 6.2 macOS

安装 **Xcode Command Line Tools**：

```bash
xcode-select --install
```

这会安装 `clang` 等编译器。确认：

```bash
clang --version
```

**注意**：Nuitka 对 macOS 的 bundle 文件在较新系统上仍存在已知问题，打包阶段需要预留调试时间。

### 6.3 Linux（Ubuntu / Debian 系）

```bash
sudo apt update
sudo apt install build-essential
```

这会安装 `gcc`、`g++`、`make` 等。确认：

```bash
gcc --version
# 要求 ≥ 5.1
```

Nuitka 要求 `gcc` 至少 5.1（或 `g++` 4.4）。建议在 **Ubuntu 22.04 LTS** 上构建，以兼顾 glibc 兼容性与 gcc 版本。

## 7. 环境验证脚本

在项目根目录创建 `scripts/verify_env.py`，运行后检查关键依赖与 Qt WebEngine：

```python
import sys

def check(label, fn):
    try:
        fn()
        print(f"[OK]   {label}")
        return True
    except Exception as e:
        print(f"[FAIL] {label}: {e}")
        return False

checks = []

checks.append(check("Python >= 3.12", lambda: (
    (_ for _ in ()).throw(AssertionError(sys.version))
    if sys.version_info < (3, 12) else None
)))

checks.append(check("NumPy", lambda: __import__("numpy")))
checks.append(check("SciPy", lambda: __import__("scipy")))
checks.append(check("pHcalc", lambda: __import__("pHcalc")))
checks.append(check("efta", lambda: __import__("efta")))
checks.append(check("cryptography", lambda: __import__("cryptography")))
checks.append(check("argon2-cffi", lambda: __import__("argon2")))
checks.append(check("Plotly", lambda: __import__("plotly")))

def check_pyside_webengine():
    from PySide6.QtWebEngineWidgets import QWebEngineView  # noqa: F401

checks.append(check("PySide6 + QtWebEngine", check_pyside_webengine))

sys.exit(0 if all(checks) else 1)
```

运行：

```bash
python scripts/verify_env.py
```

全部 `[OK]` 即环境就绪；任何 `[FAIL]` 按提示补装对应包。

## 8. 关键配置记录：PySide6 + Plotly 离线渲染

ACStudio 要求**完全离线**，Plotly 图表不能在 `QWebEngineView` 中依赖 CDN。开发阶段需提前处理 `plotly.min.js` 的本地化，否则运行时会出现 `Plotly is not defined`。

**正确做法**：

1. 将 `plotly.min.js` 放在项目资源目录（如 `ac_ui/resources/js/plotly.min.js`）。
2. 生成 HTML 时使用 `include_plotlyjs=False`，并在 HTML 中以相对路径 `<script src="plotly.min.js"></script>` 引用。
3. 调用 `QWebEngineView.setHtml(html, baseUrl)`，其中 `baseUrl` 指向 JS 文件所在目录的 `QUrl.fromLocalFile(...)`。**不要使用 `file://` 绝对路径**，Qt WebEngine 对本地文件协议有严格限制。

**最小验证片段**（在 `acstudio` 环境内运行）：

```python
from pathlib import Path
from PySide6.QtWidgets import QApplication
from PySide6.QtWebEngineWidgets import QWebEngineView
from PySide6.QtCore import QUrl
import plotly.graph_objects as go
import plotly.io as pio

app = QApplication([])
view = QWebEngineView()

fig = go.Figure(data=[go.Scatter(x=[1, 2, 3], y=[1, 4, 9])])
html = pio.to_html(fig, include_plotlyjs=False, full_html=True)

js_dir = Path("ac_ui/resources/js").resolve()
html = html.replace("</head>", '<script src="plotly.min.js"></script></head>')

view.setHtml(html, QUrl.fromLocalFile(str(js_dir)))
view.resize(800, 600)
view.show()
app.exec()
```

若图中正常出现折线，说明离线渲染链路可用；若浏览器控制台报 `Plotly is not defined`，检查 `baseUrl` 是否指向包含 `plotly.min.js` 的目录。

## 9. VS Code 配置

在项目根目录创建 `.vscode/settings.json`，固定解释器与终端行为：

```json
{
  "python.defaultInterpreterPath": "C:\\Users\\<你的用户名>\\miniconda3\\envs\\acstudio\\python.exe",
  "python.terminal.activateEnvironment": true,
  "terminal.integrated.defaultProfile.windows": "Command Prompt",
  "python.testing.pytestEnabled": true,
  "python.testing.pytestArgs": ["tests"]
}
```

**macOS / Linux** 将 `python.defaultInterpreterPath` 替换为：

```
~/miniconda3/envs/acstudio/bin/python
```

或 `~/anaconda3/envs/acstudio/bin/python`。

**选定解释器**：在 VS Code 中按 `Ctrl+Shift+P`（macOS `Cmd+Shift+P`），执行 `Python: Select Interpreter`，选择 `acstudio` 环境。终端新建时若未自动激活，手动执行 `conda activate acstudio`。

对，**调试阶段完全不用装**。在开发机上用 `python main.py` 直接运行、在 VS Code 里断点调试、跑 pytest、调 UI 和计算逻辑，这些都不经过 C 编译器，跟 Visual Studio Build Tools 没有任何关系。

它真正被触发的时机只有一个：**你第一次执行 `nuitka --standalone` 或 `--onefile` 命令**。在那之前，装不装都不影响开发。

几个具体节点可以对照：

| 阶段 | 是否需要 Build Tools |
|---|---|
| 第 0—8 步：写代码、跑测试、调 UI、接数据层 | 不需要 |
| 第 9 步：PyArmor 加密 `ac_core`/`ac_auth` | 不需要（PyArmor 不调用 C 编译器） |
| 第 10 步：本机试跑 `nuitka --standalone main.py` | **需要**，第一次编译会报“No C compiler found” |
| 第 10 步：CI 里的 Windows runner | 不需要你本机装，GitHub Actions 的 `windows-latest` 自带 MSVC |

所以务实的做法是：**把安装 Build Tools 放到第 10 步开始之前**，当作“进入打包阶段”的前置准备，而不是现在开发环境配置的一部分。你现在把 `requirements-runtime.txt` 和 `requirements-dev.txt` 装完、`scripts/verify_env.py` 全绿，就可以直接进入第 0 步写 `tools/build_data_pack.py` 和 `data/schema.sql`。

开发记录里可以加一条状态说明，避免以后自己或协作者困惑：

| 日期 | 项目 | 状态 | 备注 |
|---|---|---|---|
