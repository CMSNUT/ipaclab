自建图床Github+PicGO

::: cautiong 关闭网络加速

不知道啥原因，PicGo上传图片到github，必须关闭watt toolkit的网络加速

DS解释：Watt Toolkit 的“中间人”加速机制与 PicGo 严格的 SSL 证书验证策略不兼容导致的。最简单的做法是在上传时关闭加速。 :::

📥 一、软件下载与官方文档

PicGo 官方下载

PicGo 是开源软件，官方发布渠道为 GitHub Releases。

  • 官方 Releases 页面（直接下载安装包）： https://github.com/Molunerfinn/PicGo/releases

  • 国内访问 GitHub 下载可能较慢，可以稍后重试，或使用镜像加速。

PicGo 官方文档

PicGo 的文档体系已迁移至统一入口，推荐使用以下链接：

  • PicGo Docs 主入口：https://docs.picgo.app/
  • 桌面端快速开始：https://docs.picgo.app/gui/guide/getting-started.md
  • GitHub 图床配置专属页（旧版文档，步骤清晰）： https://picgo.github.io/PicGo-Doc/zh/guide/config.html#github图床

🗂️ 二、GitHub 侧准备

1. 创建图床仓库

  1. 登录 GitHub，点击右上角 +，选择 New repository。
  2. 仓库名任意，例如 img-bed。
  3. 必须选择 Public（公开）。私有仓库的 Raw 链接无法被公网直接访问，图床会失效。
  4. 可以勾选 Add a README file，也可以不勾选，不影响使用。
  5. 点击 Create repository。

2. 生成 Personal Access Token（Token）

Token 是 PicGo 向仓库写入图片的“钥匙”。

推荐方案：Classic Token（repo 权限）

这是最通用、兼容性最好的方式。

  1. 点击 GitHub 头像 → Settings。
  2. 左侧菜单滚动到底部，点击 Developer settings。
  3. 选择 Personal access tokens → Tokens (classic)。
  4. 点击 Generate new token (classic)。
  5. 填写 Note（例如 PicGo），Expiration 可按需设置（不放心可设较长时效）。
  6. 勾选 repo 权限。这一项就足够了，它会赋予 PicGo 读写仓库的权限。
  7. 点击 Generate token。
  8. 立即复制生成的 Token（以 ghp_ 开头），离开页面后无法再次查看。

备选：Fine-grained Token（权限更细，但配置略繁琐） 如果你希望遵循最小权限原则，可以在 Fine-grained tokens 中生成，仅授权那一个图床仓库，权限选择 Contents → Read and write 即可。但对新手来说，Classic Token + repo 更直接。

⚙️ 三、PicGo 配置 GitHub 图床

打开 PicGo 客户端，点击左侧 图床设置 → GitHub，按下表填写：

配置项填写内容说明
仓库名 (Repo)你的GitHub用户名/仓库名例如 zhangsan/img-bed
分支名 (Branch)main 或 master必须与仓库实际默认分支一致
Token粘贴刚才复制的 Token以 ghp_ 开头
存储路径 (Path)例如 images/，或留空留空则图片存放在仓库根目录；如果填写，建议以 / 结尾，避免路径拼接问题
自定义域名见下方“加速与域名”一节可选，但强烈建议配置

填写完成后，点击 确定，再点击 设为默认图床。

🚀 四、上传测试与链接格式

在 PicGo 主界面 上传区 选择 GitHub 图床，拖入或选择一张图片上传。

  • 如果未配置自定义域名，PicGo 返回的链接格式为： https://raw.githubusercontent.com/用户名/仓库名/分支名/路径/文件名

  • 上传成功后，链接会自动复制到剪贴板，可直接粘贴到 Markdown 编辑器中。

🌐 五、加速与自定义域名（可选但推荐）

raw.githubusercontent.com 在国内访问可能不稳定。推荐使用 jsDelivr 免费 CDN 作为自定义域名。

在 PicGo 的 自定义域名 字段中填写：

https://cdn.jsdelivr.net/gh/你的GitHub用户名/你的仓库名

如果仓库的默认分支不是 main，或需要指定分支，可以加上 @分支名：

https://cdn.jsdelivr.net/gh/用户名/仓库名@分支名

配置后，PicGo 生成的图片链接会自动变为 jsDelivr 地址，国内外访问速度通常明显改善。

🔧 六、常见问题与排错

1. 上传失败，提示 401 或 Bad credentials

  • Token 过期或复制不完整，重新生成并粘贴。
  • 生成 Token 时未勾选 repo 权限，PicGo 没有写入权限。

2. 上传成功，但图片链接打不开

  • 仓库是 Private 状态。图床仓库必须是 Public。
  • 使用了 raw.githubusercontent.com 但在当前网络下无法访问，改用 jsDelivr 自定义域名。

3. 上传成功，但仓库里找不到文件

  • 存储路径 (Path) 末尾缺少 /，可能导致路径拼接异常。建议写成 images/ 或直接留空。

4. 每次上传同名文件失败

GitHub 不允许同名文件覆盖上传。可以在 PicGo 设置中开启 时间戳重命名，避免文件名冲突。

5. 找不到 Developer settings

在 GitHub Settings 页面，左侧菜单滚动到最底部即可看到；也可以直接访问： https://github.com/settings/tokens
